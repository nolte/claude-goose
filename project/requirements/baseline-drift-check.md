## Bounded context

- **What**: a Goose recipe that checks one published baseline revision for source drift — for
  every source record in that revision's `sources.md`, compare the recorded `source_commit` with the
  current commit of the same upstream documentation file, and print the rows an operator appends
  to `verification.md`.
- **For whom**: the maintainer of `baselines/`, performing Stage 2 of `baselines/MAINTENANCE.md`,
  which is done by hand today.
- **Out of scope**: writing to `verification.md` or any file; deciding what a drift means; fetching
  page content; revisions that are not published; anything about criteria.

## Requirements

- **R1** — WHEN given a revision id, the recipe SHALL read
  `<baselines_dir>/goose/<revision>/sources.md` and extract every record's id, `source_path` and
  `source_commit`.
  - _dimension_: `functional` · _status_: `confirmed` · _source_: "MAINTENANCE.md Stage 2"
- **R2** — WHEN a record carries a `source_path`, the recipe SHALL query the upstream repository
  for the latest commit touching that path and compare it with the recorded `source_commit`.
  - _dimension_: `functional` · _status_: `confirmed` · _source_: "MAINTENANCE.md: `gh api repos/<repo>/commits?path=<path>&per_page=1`"
- **R3** — WHEN all records are compared, the recipe SHALL print one `verification.md` table row
  per record: date, source id, rule, observed commit, result `unchanged` or `drifted` — the
  vocabulary `SOURCE-FORMAT.md` defines for `verification.md`, so a row pastes in unchanged.
  - _dimension_: `acceptance_criteria` · _status_: `confirmed` · _source_: "verification.md format"
- **R4** — The recipe SHALL run without a person at the keyboard.
  - _dimension_: `non_functional` · _status_: `confirmed` · _source_: "maintainer: run it from a task or a schedule"
- **R5** — The recipe SHALL NOT write to any file, SHALL NOT modify anything under the baselines
  directory, and SHALL NOT use HTTP `ETag` or `Last-Modified` to decide drift.
  - _dimension_: `constraints` · _status_: `confirmed` · _source_: "MAINTENANCE.md; append-only verification log"
- **R6** — WHEN the upstream query fails for a record (not authenticated, path gone, rate limit),
  the recipe SHALL print that record's row with result `unreachable` and the reason, and continue.
  - _dimension_: `edge_cases` · _status_: `confirmed` · _source_: "author decision"
- **R7** — WHEN the revision directory or its `sources.md` does not exist, the recipe SHALL say so
  and print no rows.
  - _dimension_: `edge_cases` · _status_: `confirmed` · _source_: "author decision"
- **R8** — The upstream repository and the baselines directory SHALL be overridable inputs with
  defaults `aaif-goose/goose` and `./baselines`.
  - _dimension_: `constraints` · _status_: `assumed` · _source_: "CLAUDE.md drift command names aaif-goose/goose"

## Surviving assumptions / open risks

- R8 is `assumed`: the maintainer has not confirmed that the repository should be an input rather
  than fixed. Kept as an input because `SOURCE-FORMAT.md` records the `block` → `aaif-goose`
  transfer, so the value has already changed once.
- Whether a record without `source_path` (evidence class B, index-derived) should produce a row at
  all is not stated in `MAINTENANCE.md`; this artifact says `unreachable` with reason "no source_path".
- Revised 2026-09-24 after the first `recipe-plan` run: the result vocabulary was `unchanged` /
  `changed` / `unknown`, which does not match `SOURCE-FORMAT.md`; the plan followed it literally
  and flagged it. Corrected here, at the level whose decision caused it.
